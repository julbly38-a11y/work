# work — пошук роботи

Приватна панель власника: вакансії з Upwork, моніторинг ринку праці та канон замовників. Дані лежать у Supabase, сайт розгортається на Vercel.

## Сторінки (вкладки в `index.html`)

| Вкладка | Що показує | Джерело |
|---|---|---|
| **Upwork** | вакансії з фільтрами (тип оплати, бюджет, тема, конкуренція, клієнт, період), сортування «кращі можливості», деталі українською й англійською, посилання на оригінал | `/api/vacancies` → таблиця `upwork_vacancies` |
| **Ринок праці** | знахідки моніторингу з інших джерел | `/api/market` → `job_market_postings`, `job_market_state` |
| **Замовники** | канон замовників: оцінка, відповідність, витрати, hire rate, вердикт, його вакансії | `/api/clients` → `clients` |

Теми, бюджетні діапазони, якість клієнта й «кращі можливості» обчислюються на клієнті з наявних полів (див. `enrich()` в `index.html`).

## Доступ

Увійти може лише власник:

1. вхід через Supabase Auth (email + пароль);
2. API перевіряють токен, підтверджений email власника і роль `admin` у `app_users` (`api/_owner.js`);
3. ключ `SUPABASE_SERVICE_KEY` використовується лише на сервері й ніколи не потрапляє в браузер.

Публічний `anon`-ключ у `index.html` потрібен тільки для входу.

## API

| Ендпоінт | Таблиці | Примітки |
|---|---|---|
| `GET /api/vacancies` | `upwork_vacancies` | до 2000 рядків, нові першими; віддає `type`, оплату, клієнта, описи |
| `GET /api/market` | `job_market_postings`, `job_market_state` | до 1000 рядків |
| `GET /api/clients` | `clients` | до 2000 рядків, за оцінкою й витратами |

Усі повертають `401`, якщо запит не від власника. Відповіді не кешуються (`Cache-Control: no-store`).

## Змінні середовища (Vercel)

| Змінна | Призначення |
|---|---|
| `SUPABASE_URL` | адреса проєкту Supabase |
| `SUPABASE_SERVICE_KEY` | серверний ключ (секрет) |
| `OWNER_EMAIL` | необов'язково; за замовчуванням `julbly38@gmail.com` |

## Таблиці Supabase

- `upwork_vacancies` — вакансії Upwork (назва, оплата, країна клієнта, заявки, описи EN/UK, `client_info` JSON).
- `job_market_postings`, `job_market_state` — моніторинг ринку праці.
- `app_users` — ролі користувачів (потрібна роль `admin`).
- `clients` — **канон замовників**: ідентифікація, надійність (витрати, hire rate, відгуки), поведінка (швидкість найму, типові бюджети), сезонність, `our_fit` і `score` (1–5), вердикт, `watch`, відбиток для моніторингу, історія вакансій, наша взаємодія. Усі записи, крім №1, виведені з `upwork_vacancies` за відбитком (країна, штат, вакансії, відгуки, оцінка, витрати), бо Upwork не віддає id замовника; один замовник може розділитися на два рядки, якщо його статистика змінилась.
- Допоміжні, поза сайтом: `counties`, `property_classes`, `county_property_classes`, `county_property_classes_flat` (довідник класів власності для 15 округів Індіани).

RLS увімкнено на нових таблицях без публічних політик: читає лише сервер із `service`-ключем.

## Локальний запуск

Сайт статичний, функції в `api/` працюють на Vercel. Локально без API сторінка падає на запасні дані з `data.js` (якщо файл є); для повної перевірки використовуйте `vercel dev` із налаштованими змінними середовища.

```bash
vercel dev
```

## Розгортання

Пуш у `main` запускає розгортання на Vercel автоматично. Файл `.vercelignore` виключає `data.js` і `.env*`.

## Окремі робочі матеріали (не входять у розгортання сайту)

- `county-data/` — довідник класів власності по округах, демо-файл для відгуку, скрипти.
- `vacancy-report/` — статичний звіт по вакансіях.
- `athena-audit/` — шаблони методики й листа до замовника.
